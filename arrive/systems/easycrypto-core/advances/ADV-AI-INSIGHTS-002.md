## Objective

**Part 2 of 4** of the on-device AI insights feature. Introduce the Apple
**Foundation Models** dependency and the `FoundationModelInsightEngine` that turns
the bounded `TradeSummary` from ADV-AI-INSIGHTS-001 into validated
`GeneratedInsight` values — running **entirely on device** (iOS 26+), with no
network and no remote/cloud fallback. Depends on ADV-AI-INSIGHTS-001
(`TradeSummary`).

## Behavioral Change

After this advance:
- Calling the engine with a `TradeSummary` produces validated `GeneratedInsight`
  values generated by an **on-device** `LanguageModelSession`
  (`SystemLanguageModel.default`).
- Output uses **guided generation**: a `@Generable` `TradingInsightDraft`
  (constrained fields + `@Guide` descriptions), batched in `InsightDraftBatch`, is
  requested via `session.respond(to:generating:)`, then mapped to `GeneratedInsight`
  — no free-text parsing.
- `GeneratedInsight` is a `Sendable` value (not the `@Model TradingInsight`); the
  persisted model is created at the persistence boundary (Parts 3/4) so the engine
  stays off the main actor and free of SwiftData.
- The engine exposes `checkAvailability()` (mapping
  `SystemLanguageModel.default.availability` to `available` / `unavailable(reason)`)
  and `generate` **gates** on it: when unavailable it throws
  `InsightEngineError.unavailable` *without* calling the model, so unsupported
  devices degrade gracefully.
- The engine is reachable only through a protocol seam so its mapping/availability
  logic is unit-tested with a fake session — no real LLM call in tests.
- No UI and no background scheduling yet (Parts 3 and 4).

## On-Device-Only Constraint (non-negotiable)

- Uses **only** `import FoundationModels` / `SystemLanguageModel.default`.
- The engine performs **no** `URLSession`/network I/O and consumes only the
  in-memory `TradeSummary` (never raw trades).
- No prompt or summary is logged off-device or sent to analytics.

- **ai-insights** (`EasyCrypto/Core/AI/**`):

  - Add `InsightCategory`/`InsightSeverity` vocab enums + `GeneratedInsight`
    (`Sendable` value) and a pure `InsightDraftMapper` (normalizes category/severity,
    drops empty drafts, empty symbol -> nil).
  - Add an `InsightDraftGenerating` protocol seam with a thin production adapter
    (`LanguageModelInsightSession`) over `LanguageModelSession`; tests inject a fake.
  - Add `FoundationModelInsightEngine` (struct-with-closures): `checkAvailability`
    maps `SystemLanguageModel.default.availability`; `generate` gates on it, builds a
    compact instruction + prompt from `TradeSummary` (`InsightPrompt`), requests
    `InsightDraftBatch` via guided generation, and maps drafts -> `GeneratedInsight`.
    No `@available` needed (app deployment target is iOS 26.0).

## Risk + Rollback

- Risk: new_dependency — adopts the `FoundationModels` framework; guard all use
  behind `SystemLanguageModel.default.availability` and `@available(iOS 26, *)` so
  unsupported devices degrade gracefully instead of crashing.
- Risk: privacy — keep the engine path free of any network I/O and ensure only the
  bounded `TradeSummary` (never raw trades) is passed to the model; never log
  prompts/summaries off device.
- Risk: nondeterminism — use guided generation (`@Generable`) for typed output and
  isolate the model behind the `InsightSession` seam so engine logic is testable
  without invoking the LLM.
- Risk: concurrency — engine runs off the main actor; keep inputs/outputs `Sendable`.
- Rollback: engine is unused by any surface until Part 3/4; revert the advance's
  commits.

## Design Note — GeneratedInsight vs @Model

The engine outputs a `Sendable` `GeneratedInsight` value rather than the `@Model
TradingInsight`. Constructing SwiftData models off the main actor is unsafe; keeping
the engine's output a plain value lets it run off-actor (Part 4) and defers `@Model`
creation to the persistence boundary (Parts 3/4). This refines the original wording
("drafts -> TradingInsight") without changing the externally observable behavior.
